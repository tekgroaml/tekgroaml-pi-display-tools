# 设备条目与脚本命名

2.3.0起，客户查找名称与脚本标识分开管理。

## 客户识别名

采用“尺寸＋分辨率＋形状/触摸类型”，例如：

- **4.0英寸 720×720 方形触摸屏**。
- **6.2英寸 420×960 长条触摸屏**：420×960为已验证输入模式，厂家原生规格待核对。
- **6.2英寸 420×960 长条非触摸屏**：单独记录，当前无已验证修复脚本。

这是支持资料中的产品条目，不代替SKU、ASIN、厂家料号或批次。尺寸由卖家或客户资料确认，不从EDID的物理尺寸自动推断；没有型号就写待确认。

## 正式脚本ID和文件名

```text
<尺寸>inch-<宽>x<高>-<目标刷新率>hz-<驱动上报标识>
```

正式ID用于`--profile`，同名加`.sh`后是便捷脚本文件。驱动名是EDID报告标签的标准化写法，不是读取到真实芯片型号的声明。名义60Hz仍可对应实际60.004Hz，精确值在修复数据中记录。

| 客户产品 | 正式ID | 旧别名 |
| --- | --- | --- |
| 4.0英寸720×720方形触摸屏 | `4.0inch-720x720-60hz-wks-lontium-semi` | `lontium-720` |
| 6.2英寸420×960长条触摸屏 | `6.2inch-420x960-60hz-ltm-zl480` | `ltm-420x960-60` |

不同变体若四个字段相同但修复不同，追加`touch`/`nontouch`、控制器修订号或已核对的SKU后缀，不把另一种修复覆盖到旧ID上。相同EDID也不保证物理产品一致；非触摸款不能仅凭数据相同套用触摸款修复。

旧名保留为别名；开机读取旧保存项时会解析为相同修复。新命令保存使用正式ID，已有配置无需手工改名。应用版本、命令接口版本和配置格式版本仍是独立概念。

## 查询设备卡片

```bash
screen-config profiles
screen-config profiles --json
```

文本展示客户名称、驱动标识、原始/修复模式及像素时钟、问题、适用范围和别名。JSON还包括尺寸、触摸类型、厂商/产品标识、EDID长度、完整前后沿及精确刷新率。代码中的`PROFILES`是程序元数据来源，不能给未验证款添加看似已经修复的卡片。

## 使用正式ID

以接口1为例，临时应用：

```bash
screen-config apply --port 1 --profile 4.0inch-720x720-60hz-wks-lontium-semi
screen-config apply --port 1 --profile 6.2inch-420x960-60hz-ltm-zl480 --confirm-profile
```

这两条命令分别用于两款不同产品，不要对同一设备连续套用。应用前保存图形文件，EDID覆盖可能重启桌面。先观察实体结果，验证成功后加`--save`。

安装2.3.0后也可在源码目录中使用同名脚本：

```bash
bash scripts/profiles/4.0inch-720x720-60hz-wks-lontium-semi.sh --port 1
bash scripts/profiles/6.2inch-420x960-60hz-ltm-zl480.sh --port 1 --confirm-profile
```

`.sh`只是统一`screen-config apply`的便捷入口，所有EDID匹配、确认、保存和恢复逻辑仍由同一应用实现，不刷屏幕固件。临时模式无自动恢复计时器；需要恢复时运行：

```bash
screen-config auto --port 1 --save
```

## 统一产品信息卡字段

1. 产品基本信息：名称、尺寸、分辨率含义、触摸类型、SKU/厂家料号/批次。
2. 驱动上报数据：EDID名称及标识、模式、像素时钟、刷新率、同步前后沿、适用的USB触摸标识。
3. 简述问题：症状、影响平台和失败变体。
4. 修复数据：修改前后对照、哪些参数保持不变及实物结果。
5. 修复脚本：正式ID/文件、应用版本、临时/保存/恢复命令、确认条件。
6. 验收边界：画面、触摸、冷启动及批次差异的已通过/未验证状态。

客户卡片、目录及模板位于支持仓库的`product-support/`下：

```text
https://github.com/tekgroaml/tekgroaml-display-support/tree/main/product-support
```
