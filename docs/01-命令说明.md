# 树莓派屏幕配置与颜色测试命令

验证环境：Raspberry Pi 4 Model B，Raspberry Pi OS Bookworm Desktop 64 位，labwc / Wayland。需要在树莓派已登录桌面的情况下运行；可以从 SSH 执行。其他树莓派型号、X11、无桌面系统不在本版支持范围。

## 接口与屏幕编号

| 物理接口 | 配置命令参数 | 颜色测试参数 | Linux 接口 |
| --- | --- | --- | --- |
| HDMI0，靠近 USB-C 电源口 | `--port 1` | `--screen 1` | `HDMI-A-1` |
| HDMI1，远离 USB-C 电源口 | `--port 2` | `--screen 2` | `HDMI-A-2` |

`--port`和`--screen`统一使用Linux接口编号1、2：数字1对应`HDMI-A-1`，数字2对应`HDMI-A-2`。板子标号仍为HDMI0/HDMI1，不作为命令数字。`--screen` 是接口的固定别名；换屏后仍保持同一编号，不按桌面左右位置重新编号。分辨率不等于英寸尺寸，程序不会根据不可靠的 EDID 物理尺寸推断实际英寸数。

升级说明：旧版配置命令使用0、1；新版原来的`--port 0`改为`--port 1`，原来的`--port 1`改为`--port 2`。测试命令原本就是1、2，无需改号。已保存配置无需手动修改。详见[变更记录](../CHANGELOG.md)。

## 一、显示配置 screen-config

### 查看连接与模式

```bash
screen-config list
screen-config modes --port 2
screen-config profiles
screen-config profiles --json
```

`list` 显示连接状态、屏幕名称、当前模式、是否有 EDID 覆盖和已保存配置。`modes` 显示系统已接受的模式。名称来自驱动板写入的信息，可能不等于真实产品型号。

### 设置当前输出

```bash
screen-config set --port 1 --mode 480x480@60
screen-config set --port 2 --mode 800x800@60
```

只接受当前屏幕已报告的模式；刷新率允许 0.1Hz 内的四舍五入差异，例如 `60` 可匹配 `60.004`，但不会匹配 `59.94` 与 `60` 中的错误优先项。先选差值最小的模式。

默认临时生效，重启后回到桌面的默认模式；桌面自身保存的设置可能影响最终启动结果。加 `--save` 才由本程序在后续桌面登录时重新应用：

```bash
screen-config set --port 2 --mode 800x800@60 --save
```

保存按“接口＋屏幕 EDID 身份”绑定。换成其他屏幕时跳过旧设置，不强制套用。相同 EDID 的设备无法区分，驱动板序列号缺失或重复时请自行复核。

### 更换屏幕后重新识别

```bash
screen-config auto --port 2
screen-config auto --port 2 --save
```

`auto` 清除本程序管理的旧 EDID 覆盖，重新探测当前屏幕，再应用首选模式。必要时重启桌面，两块屏幕可能短暂黑屏，桌面中的未保存窗口会关闭，请提前保存文件。另一个接口不修改分辨率配置。

`auto --save` 还删除该接口由本程序保存的开机配置。未加 `--save` 时，已有保存项在下次启动仍可能生效。

本程序不会清除来源不明的 EDID 覆盖。对于本次测试产生的旧 `pi-hdmi-720-compat` 覆盖，安装程序会备份并接管；未知工具写入的覆盖需先联系维护者。

### 已知 720×720 方屏兼容配置

```bash
screen-config apply --port 2 --profile 4.0inch-720x720-60hz-wks-lontium-semi
screen-config apply --port 2 --profile 4.0inch-720x720-60hz-wks-lontium-semi --save
```

仅匹配已知 WKS / Lontium 驱动板和已验证时序。该配置将水平同步宽度调整为 6 像素，像素时钟设置为 38.54MHz，得到约 60.004Hz；不写屏幕固件。不同批次或未知时序拒绝应用。

临时应用也会记录覆盖来源，以便之后 `auto` 安全清除，但不会自动保存为开机设置。

### 6.2英寸触摸样机：420×960 / 60Hz

仅限卖家确认与成功样机相符的触摸变体，2.3.0起使用以下正式名称（2.2的旧名继续兼容）：

```bash
screen-config apply --port 1 --profile 6.2inch-420x960-60hz-ltm-zl480 --confirm-profile
```

保留420×960有效像素、同步极性及前后沿，只将像素时钟28MHz改成32.4MHz，得到60Hz。确认画面完整稳定后再保存：

```bash
screen-config apply --port 1 --profile 6.2inch-420x960-60hz-ltm-zl480 --confirm-profile --save
```

EDID检查仍然执行，`--confirm-profile`不能绕过数据匹配。已测试的非触摸样机报告相同EDID，但使用同样参数仍有异常；软件无法从相同数据区分实体变体，因此要求用户确认指南。厂家型号尚未确认，配置名不是型号认证。换屏前后请用`screen-config auto --port 1 --save`清除旧配置，再验证。

本命令没有自动恢复倒计时；临时试用失败应手动执行`auto --save`恢复。详细步骤和适用范围见[6.2英寸产品指南](06-6.2英寸长条屏.md)。应用时可能重启整个桌面，请先保存文件。

### 权限和开机设置

查询命令不需要 root；修改命令会调用 `sudo`，可能要求输入树莓派系统密码。不会把密码存到代码中。

`--save` 的配置存放在 `/etc/pi-setting/config.json`。开机服务在桌面启动前应用已保存兼容配置，桌面自动启动项再恢复指定模式。开机自动登录桌面或手动登录桌面后才会运行颜色测试和桌面模式恢复。

```bash
screen-config restore
```

这是手动重新应用已保存设置的命令，通常由桌面自动启动项执行。保存的普通模式只在屏幕身份匹配时应用；兼容配置保存后同样绑定屏幕身份。

正式配置ID和同名`.sh`入口按“尺寸＋分辨率＋刷新率＋驱动上报标识”命名，客户显示名按尺寸和分辨率查找。产品卡片包含驱动上报、问题和修复数据。旧别名继续兼容，完整规则见[设备与脚本命名](07-设备条目与脚本命名.md)。

## 二、全屏测试 screen-test

### 同步控制全部已连接屏幕

```bash
screen-test black
screen-test white
screen-test red
screen-test pattern
```

分别显示纯黑 `#000000`、纯白 `#FFFFFF`、纯红 `#FF0000`。图案模式包含方形边界、内切圆、网格、方向标记、中心十字和接口编号。圆屏会遮挡方形四角，请以圆周及径向标记判断圆形可视范围。

### 分别控制

```bash
screen-test white --screen 1
screen-test red --screen 2
screen-test pattern --screen 2
```

未指定的屏幕保持原有测试状态；首次启动只覆盖指定屏幕，不影响另一块桌面。

### 触摸操作测试

```bash
screen-test touch
screen-test touch --screen 1
screen-test touch --screen 2
```

显示五个编号靶点（中心和上下左右，位于圆屏可见范围内）。用手指直接点靶点，点中变绿；触摸计数、坐标和白色触点会更新，滑动留下蓝色轨迹。`RESET` 按钮清空该屏的测试记录。重新执行 `touch` 也会清空所选屏幕记录。接收桌面实际交给窗口的原生触摸，以及鼠标/触摸模拟鼠标输入；界面和状态分别标注 NATIVE TOUCH 与 POINTER / EMULATED TOUCH。后者无法仅凭协议区分真实鼠标与触摸模拟，验证时请只用手指操作。

检查方法：五个点均能点绿、触点跟随手指、拖动轨迹连续，并且点击哪个实体屏幕就由哪个屏幕响应。5/5只说明这些采样位置点中，不代表全屏校准、边缘或多点触控全面验收。如果触摸无响应、位置偏移或另一块屏幕响应，需排查桌面触摸映射；本模式不会自动修改映射，也不会根据原始坐标伪造本屏点击结果。

`screen-test status` 会显示各屏点击次数、命中数量和最近触点。运行时仍需保持桌面登录。退出用 `screen-test stop`。

### 自动循环

```bash
screen-test cycle --interval 5
screen-test cycle --interval 10 --screen 2
```

按黑 → 白 → 红循环，每种颜色保持指定秒数。默认 5 秒，最小 0.2 秒。切换静态颜色会取消对应屏幕的循环。

### 点击切色：同时测试颜色与触摸

```bash
screen-test tap-cycle
screen-test tap-cycle --screen 1
screen-test tap-cycle --screen 2
```

初始显示纯黑，每次手指按下切换一次：黑 → 白 → 红 → 黑。没有定时切换；不点击就一直保持当前颜色。两块屏幕独立变化，点击①号屏不会切换②号屏，因此也能观察触摸是否串屏。

画面保持纯色，不叠加文字、靶点或触点。长按、拖动和抬起不额外切色；多个手指同时接触时只切换一次，全部抬起后下一次按下才再次切换。重新执行命令会把选中的屏幕重置到黑色。

支持原生触摸和鼠标模拟触摸；真实鼠标点击也能触发，请只用手指验证触摸。`screen-test status`可查看各屏当前颜色和切换次数。此模式验证事件能到达并触发切色，不验证坐标精度；坐标与轨迹仍用`screen-test touch`。退出使用`screen-test stop`。

### 状态与退出

```bash
screen-test status
screen-test stop --screen 2
screen-test stop
```

`stop --screen 2` 只关闭②号屏测试，`stop` 退出整个测试程序。程序以运行命令的桌面用户启动，覆盖顶层面板、隐藏窗口边框和鼠标指针，退出后恢复桌面；不修改分辨率，也不开机自动显示测试画面。

通过 SSH 断开连接后测试继续运行。测试窗口按接口映射到当前显示器，支持不同分辨率；屏幕连接、分辨率或布局改变后会重新映射。镜像布局导致两个显示器无法唯一对应时会明确报错，不冒险把图案放到错误接口。

## 常见限制

- HDMI 传画面，触摸仍需单独的 USB 数据连接。本工具不安装或校准触摸驱动。
- 测试纯色只能检查可视异常，不代表进行过色彩校准、亮度校准或认证。
- 屏幕无画面时用 SSH 执行 `screen-config list`，先确认连接与模式，勿盲目强制自定义时序。
- 旧系统缺少 layer-shell 组件时运行安装脚本补齐依赖；本工具不支持直接在 macOS 显示树莓派测试画面。
- 当前DDC读取支持基础EDID和一个扩展块；更多扩展块会明确报错，需扩展读取支持后再使用保存/重新识别命令。

## 三、版本与升级 pi-setting

```bash
pi-setting version
pi-setting version --json
screen-config --version
screen-test --version
pi-setting check-update --source ~/pi-setting
sudo pi-setting upgrade --source ~/pi-setting
```

比较的是已下载源码目录与已安装程序，不会联网查询或下载。`--allow-major`允许已审阅的跨主版本升级，`--reinstall`修复同版本；降级与未知配置格式会被拒绝。完整规则、备份及故障回退范围见[版本与升级](05-版本与升级.md)。旧版没有`pi-setting`命令时，先用新包的安装脚本完成首次升级。
