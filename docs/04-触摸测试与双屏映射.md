# 在屏幕上直接测试触摸

## 使用

```bash
screen-test touch
```

每个屏幕显示中心和四个方向的5个编号靶点。用手指点靶点：命中后变绿，计数增加；滑动时应看到蓝色轨迹跟随手指。`RESET` 重新开始该屏的测试。

```bash
screen-test touch --screen 1
screen-test touch --screen 2
screen-test status
screen-test stop
```

应验证：点击哪个实体屏幕就由哪个屏幕响应、触点接近手指位置、五个靶点均可点中、轨迹基本连续。5/5只验证这些采样点，不代表全屏校准或全部多点触控能力已验证。

`NATIVE TOUCH` 代表收到原生触摸事件；`POINTER / EMULATED TOUCH` 代表鼠标协议输入，它可能来自桌面的触摸模拟鼠标，也可能是真实鼠标。因此验证时请仅用手指。

## 颜色＋触摸联合测试

```bash
screen-test tap-cycle
screen-test tap-cycle --screen 1
screen-test tap-cycle --screen 2
```

初始纯黑，用手指按一下变白，再按变红，再按回黑。不操作时颜色保持不变，没有定时器。长按或拖动只切换一次，多指接触时需全部抬起后再按才会切换下一次。

颜色保持全屏纯色，不绘制标签、触点或轨迹。①②号屏独立变化，可同时观察颜色均匀性、触摸输入能否触发、是否串屏。点击能切色不代表坐标精度已验证；坐标测试仍使用上面的`touch`模式。真实鼠标也能触发，验证触摸时请只用手指。

用`screen-test status`查看当前颜色和切换次数，`screen-test stop`退出。

## 同名双触摸屏串屏

不同屏幕可能报告相同USB名称，且缺少唯一序列号。仅按设备名称配置时，两块触摸控制器可能落在同一输出。

先一次只触摸一块实体屏幕，结合输入事件确认它对应的原始输入节点与USB物理路径；再对另一块屏幕重复。不要使用示例中的节点作为已确认配对，也不要按设备出现顺序猜测。

某些桌面版本不会采用`WL_OUTPUT`等设备属性，应按实际输入行为验证。受支持的Bookworm/labwc环境可选用USB路径输入中转服务，为同名设备生成不同名称，再分别关联输出：

| 虚拟设备名称 | 输出 |
| --- | --- |
| `PiSetting Touch HDMI0` | HDMI-A-1 / ①号屏 |
| `PiSetting Touch HDMI1` | HDMI-A-2 / ②号屏 |

输入中转不变换坐标，不将原始事件直接画到指定屏幕来绕过桌面映射。测试窗口仍验证桌面实际送达的原生触摸事件。服务对已配置的两个物理控制器独占读取，避免同一触摸同时从原始和虚拟设备重复进入桌面；停止服务会关闭虚拟设备并释放物理控制器。

## 可选部署（仅同名双控制器需要）

先通过“仅触摸一块屏幕”的实际事件确认对应设备，不能仅凭event编号猜测。通用安装不会自动启用中转，单屏正常时无需启用。程序和依赖：

```bash
sudo apt-get install python3-evdev
cd ~/pi-setting
sudo bash scripts/install.sh
sudo python3 scripts/configure-touch-map.py \
  --screen1-device /dev/input/eventN \
  --screen2-device /dev/input/eventM \
  --user YOUR_DESKTOP_USER
```

`eventN`、`eventM`和`YOUR_DESKTOP_USER`均为占位符，必须改成当前机器已确认的原始输入节点和桌面用户名。基础安装目录不强制要求为`~/pi-setting`，请进入自己的代码目录；`--no-deps`只适用于依赖已经齐全的环境。设置程序将当前设备解析成稳定USB物理路径，写入 `/etc/pi-setting/touch-map.json`，并在用户labwc配置中追加本程序两个设备名称的映射。原始配置保存在 `/var/lib/pi-setting/backups` 中。

配置完成后，需要从桌面用户的SSH终端重新加载labwc设置。若只有一个该用户的labwc进程：

```bash
pkill -HUP -u "$(id -u)" -x labwc
screen-test touch
```

多桌面会话时请先确认目标PID，不要向所有进程发信号。重新加载会暂时影响输入配置。

不能把其他机器的USB路径套给自己的设备。每个USB数据口必须与对应HDMI屏幕保持配对；交换USB插口或改变HDMI和屏幕对应关系后，需重新确认绑定。event编号会变化，不作为持久绑定条件。

服务与日志：

```bash
systemctl status pi-setting-touch.service
journalctl -b -u pi-setting-touch.service --no-pager
```

## 回退

停止中转并释放物理设备：

```bash
sudo systemctl disable --now pi-setting-touch.service
```

随后可以移除用户 `~/.config/labwc/rc.xml` 中本程序添加的两个 `PiSetting Touch HDMI` 配置项，再重新加载桌面设置。通用卸载脚本也会停止已安装的中转服务并移除这两个配置项，保留原始备份及touch-map.json。

具体备份子目录由配置程序在当前机器上生成，并在运行时打印。撤回后原先按同名设备统一映射的labwc配置仍在，可能重新出现两块屏幕都指向②号屏。
